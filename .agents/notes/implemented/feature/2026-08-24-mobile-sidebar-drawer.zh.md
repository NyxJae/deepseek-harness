# Agent Note: 移动端侧边栏使用覆盖式抽屉

Status: implemented

[English](2026-08-24-mobile-sidebar-drawer.md) | 中文

## 问题

窄屏 AppFrame 过去仍为桌面侧边栏保留 56px 轨道，使手机尺寸的对话内容永久向右缩进。轨道还会暴露多个导航控件，与有限的对话宽度争用空间。

## 决策

`AppFrame` 在 `SIDEBAR_AUTO_COLLAPSE` 以下选择覆盖模式。`computeColumns()` 在该模式下把侧边栏解析为零 grid 宽度，使对话和详情栏使用完整 frame。`sidebar` owner share 增加 `mobile`，关闭时传入零宽度，打开时传入经过约束的首选抽屉宽度。

`SidebarRoot` 在关闭状态保持子 slot 挂载，在安全区感知的左上角渲染 44px 品牌触发图标，打开状态则在对话内容上方渲染固定抽屉。展开的品牌行负责收起移动端抽屉或桌面端侧边栏；独立的 New Session 行负责新建会话。固定背景遮罩负责点击关闭，Escape 负责键盘关闭。从触发器打开时，焦点会进入抽屉中的第一个可用控件；初始或响应式出现的移动抽屉没有打开来源，因此保留文档当前焦点；每种关闭路径都会在抽屉子树隐藏前把焦点移回可见触发器。桌面端 56px 轨道和桌面端拖动行为保持不变。窄屏对话标题栏会为左侧触发图标预留空间。


## 考虑过的备选方案

**保留 56px 移动端轨道。** 否决，因为它会永久占用对话宽度，而且在用户只要求一个图标时仍显示多个控件。

**移动端打开侧边栏时挤开对话内容。** 否决，因为选定行为是覆盖在内容上方的抽屉；打开导航不应改变对话栏的宽度或滚动几何。

**在 AppFrame 中渲染通用触发图标。** 否决，因为品牌标记属于侧边栏拥有的 slot，部署方可以替换它；触发器必须和桌面品牌身份使用同一个 mark slot。

## 影响

移动端关闭侧边栏时，对话内容使用完整 frame 宽度。打开导航时增加抽屉和背景遮罩，不改变对话栏；抽屉没有缩放手柄。侧边栏浏览器 entry 在关闭时保持挂载，因此本地搜索词和浏览状态会跨抽屉切换保留；宽态专属 chrome 仍按外壳已有过渡规则卸载。打开时焦点进入抽屉，关闭时焦点回到触发器。抽屉最大宽度为视口宽度减 24px，并包含安全区内边距。

## 测试

布局求解器、AppFrame owner contract、SidebarRoot 抽屉行为、桌面端与移动端品牌操作、焦点恢复、CSS 几何、指针滚动条行为和会话标题栏间距均由聚焦客户端测试覆盖。侧栏与会话客户端 bundle 会随仓库 build 一起重建。
