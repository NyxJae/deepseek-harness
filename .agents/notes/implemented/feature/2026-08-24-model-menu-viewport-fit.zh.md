# Agent Note: 模型菜单保持在视口内

Status: implemented

[English](2026-08-24-model-menu-viewport-fit.md) | 中文

## 问题

Composer 的模型触发器可能位于视口内部，而不是右边缘。菜单原本相对触发器 wrapper 使用绝对定位，因此把 wrapper 的右边缘当作卡片右边缘；在 320px frame 中，250px 的根菜单会从 x=-49 开始，被视口裁掉。

## 决策

`ModelSelect` 将打开的菜单渲染为固定在视口上的 surface。菜单绘制后测量触发器和菜单矩形，将水平方向限制在视口 12px 内边距之内；垂直方向优先放在触发器上方，上方空间不足时改放到下方。菜单打开期间，resize 和捕获阶段的 scroll 监听器会重新计算位置。菜单仍处于组件子树内，因此点击外部和键盘归属不变。

## 考虑过的备选方案

**增大 wrapper 宽度或让菜单对齐 composer 边缘。** 否决，因为触发器在不同模式和可用控件下的位置会变化；修改 wrapper 会改变输入行，而不是解决弹出层定位。

**只用固定的移动端 CSS 偏移。** 否决，因为溢出取决于触发器位置和菜单 pane 宽度，中间视口或窗口调整后仍可能出现同一问题。

## 影响

两级模型和推理强度 pane 保持原有内容、键盘行为和宽度上限。固定 surface 不再受祖先裁剪影响，并且与每个视口边缘至少保持 12px；较高的 pane 仍使用已有的内部滚动上限。

## 测试

模型选择组件测试覆盖两级交互、选择失败处理，以及触发器偏右时的 320px 几何场景；该场景要求菜单解析到 x=12。客户端 watcher 会重建受影响 bundle，组装后的 Web GUI 可用同一矩形约束验证实时菜单。
